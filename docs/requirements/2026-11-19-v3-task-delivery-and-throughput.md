# V3 后台交付与并发性能

## 目标

补抓请求以目标季集的资源库存为交付依据。采集完成事件重复或乱序时，任务仍能结束并继续分页。后台消费持续推进，门户高并发读减少不必要的数据库借用和分类扫描。

## 设计

- Task 服务分批复查已提交的补抓请求。库存达标时记录确认时间。零结果、全失败或丢失子任务分开退避。等待入库、暂停或仍在运行的任务保持可继续复查。重试优先选择该请求尚未尝试的合格来源。
- 进度队列保留现有消息和存储键格式。登记发现事件时保留已收到的详情结果，状态和计数只推进一次。最后一批结果到达后重用现有的分页与快照流程。
- 采集和磁链沿用当前流量控制、代理、任务存储和发布确认契约。缩短临时失败对消费位的占用，保持供应商预算，并让因下游投递失败的结果可恢复交付。
- 门户沿用当前缓存与访问控制。缓存穿透时才借用数据库连接，分类内容只读取最终所需的有界候选。保持搜索、榜单和详情的既有过滤与可见性。
- 首页独立匹配 `GET /` 和 `HEAD /`。Envoy 在上游返回响应前发生连接重置时，最多重试一次。API、媒体及其他前台请求沿用现有路由。此变更随入口配置独立发布。
- HuaWai 前端使用三个现有节点分布副本，逐个滚动，主动驱逐保留两个副本。每副本限制 750m CPU 和 512Mi 内存。启动与就绪探针检查首页，存活探针检查静态版本文件。前端 DNS 优先查询完整服务名。应用制品复用已经过验证的镜像。
- Cloudflare Worker 在查找公共缓存前识别 Next.js 导航和预取。匿名 HTML 更换键版本以隔离历史对象。Worker 独立验证并发布。

## 验收

- GitHub Actions 验证真实 PostgreSQL 与 Valkey 中的补抓零结果、资源延迟到达、来源轮换、租约和乱序事件。原生镜像仅构建受影响的模块。
- 运行态复核任务终态、资源入库和可检索性。前台读压测沿用原有路径和响应断言，对比同档吞吐、尾延迟和错误，并逐档提升负载。
- HuaWai 专项压测通过生产 Envoy TLS 校验首页、浏览、搜索、详情和对应 API，总流量约 25% 为动态 HTML。固定作品与请求占比，按档限制到达速率和在途请求数。分开记录 HTML、API、尾延迟、内容校验、CPU 限流及连接池等待。
- 连接等待集中在门户查询服务时，仅调整该服务的数据库连接池。压测同时观察每个池的等待、PostgreSQL 会话和锁等待，控制滚动期的连接预算。
- 新增补抓确认时间与索引独立迁移，旧状态值保持兼容。服务回滚使用上一不可变镜像，账本中的资源确认记录仍可保留。
