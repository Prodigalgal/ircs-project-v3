# V3 Native 构建、依赖升级与虚拟线程

日期：2026-11-11

## 目标与范围

- V3、V4 均按生产就绪系统处理；本次仅改造 V3，不合并微服务，不修改 V4。
- 为 V3 Java 服务和数据库迁移器补齐 GraalVM Native/AOT 构建、运行元数据、镜像及 CI 入口，保留 JVM 构建与回退方式。
- 升级 Java 后端、管理端、门户端及 Python 分类服务至核验可获得的最新稳定依赖；排除预发布版本，记录兼容性约束。
- Java 编译和运行基线固定 JDK 25；核对 HTTP、异步任务、消息消费和自定义执行器的虚拟线程使用，保留并发限制、背压、任务取消和关闭语义。
- 同步排查并修复采集消费环节的消费超时、积压和数据库连接池耗尽：任务领取与处理能力匹配、租约所有权和超时恢复、消费线程背压、事务内外部 I/O、连接占用及失败隔离。用户没有现成日志，结论以可复现代码路径及回归测试为依据。

## 非目标

- 不更改业务 API、消息契约、数据库结构、生产数据或页面功能。
- 不执行生产发布、镜像推送、GitOps 回写或真实邮件/第三方采集。
- 不把 Python 服务转换为 GraalVM Native。

## 主要影响文件

- `backend/build.gradle`、子模块构建文件及 Gradle Wrapper。
- `backend/shared/` 的 Native 元数据和执行器，以及相关服务配置、调度和兼容性调用。
- `backend/scripts/ci/`、镜像 Dockerfile 与 `.github/workflows/`。
- 两套前端 `package.json`、锁文件及升级所需的兼容性修改。
- Python 服务 `requirements.txt`、Dockerfile 与必要的 API 兼容性修改。

## 验收和验证

1. 先记录现有测试基线，再运行升级后的 Java 全量测试、编译和打包。
2. 每个 Java 部署模块都能执行 AOT 处理；Native 任务和镜像构建支持按服务选择与多架构 CI。
3. 使用可获得的 GraalVM 25 与 C/C++ 工具链实际构建 Native 可执行文件并执行隔离 smoke；未能运行的模块必须逐项记录限制。
4. 执行虚拟线程运行断言及现有并发/背压/取消测试。
5. 两套前端完成依赖解析、构建和 lint；Python 完成依赖解析、现有测试及隔离 smoke。
6. 汇总准确版本、验证结果、兼容性影响、未验证运行态和 JVM 回退命令。
7. 为采集消费的确认根因增加超时、重投、并发和事务边界回归验证，不用无限扩容连接池或无限增加消费者代替修复。
