# 作品目录与采集流程重构

## 目标

电影、剧集、动漫、纪录片和有可信身份的综艺先入库权威作品，再搜索并核实各资源站的资源。短剧、体育赛事等缺少适用目录的类别继续按类别清洗、增强和聚合。HuaWai 首页、搜索、详情和播放沿用现有对外接口。

## 作品与资源

- TMDB 电影和电视 ID 采用每日官方清单。只有完整校验并提交的快照可供选种。热门、近期播出及有真实需求的作品优先拉取详情。提供方与媒体类型共同确定主键。
- TMDB 实际详情通过类型、ID、成人标记和标题检查后，写入权威作品。电视剧的季详情须与父级季列表一致，单集保存来源 ID、季、集与播出日。影片的投影范围为 `-1`，有明确来源证据的特别篇季号为 `0`。旧的目录请求仍用 `0` 表示不限定季。
- IMDb ID 取自 TMDB 已核实的外部映射。其他来源可提供榜单信号，作品身份仍需独立验证。IMDb 官方非商业 TSV 与当前公开站点的生产目录分开。
- 已确认作品或季映射为现有 `unified_videos`。权威详情事务完成后才建立资源补抓请求和搜索写回记录。最近更新仍需核实目标季集的播放资源。仅支持列表的源继续增量采集，关键词补抓排除已知不支持的源。
- 原始资源匹配需要类别、标题、年份和季的证据。资源站自带 ID 可帮助召回，自动绑定仍需排除矛盾与多候选。等待确认的记录保留在后台按退避重试。短剧、体育等使用既有类别策略。
- 原始记录保存来源与原始片单。权威绑定证据引用对应的原始记录与作品投影关系，解绑时一起失效。作品详情、最近更新和补抓结束条件共用同一季集校验，编号超出权威目录或显式错季的播放记录留在源数据侧供排查。

## 执行与验收

- `APP_CATALOG_AUTHORITY_FIRST_ENABLED` 统一控制新行为。旧库保留原行为，在隔离空库中启用新链路。迁移保留现有接口，并通过 GitHub Actions 的 JDK 25 测试和受影响模块 Native 构建。
- 新业务库采用独立数据库和角色、缓存状态、消息虚拟主机、搜索索引及身份签名材料。保留受保护的基础设施与授权凭据。在容量和用户允许停机的范围内，通过 GitOps 分阶段替换。
- 空库先确认迁移、管理员初始化、资源站配置、权威目录、后台队列及索引。再验证真实作品的资源补抓和播放、短剧与体育、用户注册登录及前台首页。新站通过验收后清理获准重建的旧业务数据。
