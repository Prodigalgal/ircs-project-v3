# 磁链收集质量与可靠性

## 目标与边界

通过正常系统功能解决重复任务、积压、错配及外部依赖失败；生产数据只读抽样用于评估，不执行人工批量改库、清队列或替代系统重放。保留现有管理接口、人工审核状态、业务数据及代理/连接复用能力。不下载影视或 torrent 文件，不绕过源站访问控制，不创建新的项目目录。

## 已确认的问题

- 2026-11-16 只读快照：187,210 个 PENDING 数据库任务仅涉及约 4,467 个作品；队列约 120,946 pending。自动调度只排除 RUNNING，12 小时以前的 PENDING 会重复创建。
- 搜索的整个 HTTP、流量等待及多源处理位于同一数据库事务；顺序领取批次没有续租，可能耗尽连接并重复处理。
- 多个解析器把查询 ID 复制为“匹配 ID”；75 条分源随机样本存在明确跨季错配。HTTP 200 错误页也可能被记为成功空结果。
- 基础采集链路本次检查占位 ID、无 ID 增强假成功为 0，但没有新增原始采集数据，尚不能据此证明新数据准确率。

## 实现决策

1. 搜索编排不持有数据库事务。任务创建、领取、结果持久化及终结采用短事务；以作品行锁串行化重复入队，以既有任务 version 作为执行世代并用 updated_at 续租。结果写入必须验证当前世代和有效租期，过期执行者不得提交。
2. 入队复用同作品未完成任务；自动调度排除全部 PENDING/RUNNING 并有队列背压。正常领取时合并同作品历史待执行任务，保留 SKIPPED/DUPLICATE_OF 记录，不删除历史或人工审核数据；已终结重复消息直接确认。周期性有界补投数据库待处理任务，弥补提交后队列故障。
3. 领取批次持续续租，失去队列或数据库执行权立即停止写入。有效空结果是成功；429、超时和 5xx 可有界重试，明确访问限制/配置错误不盲目重试。重试跳过本任务已成功及不可重试的 provider/query。
4. 校验真实返回标题、独立权威 ID、年份、季数和分类约束；冲突拒绝，证据不足保留 CANDIDATE，可信且 provider 允许时才自动批准。查询参数不作为独立证据。尊重 provider 声明，不强制给仅支持 IMDb 的源发送标题查询。
5. hash 统一为规范 v1 40 位十六进制；支持等价 Base32 输入，拒绝冲突 xt 和非法截断。链接并发写入幂等并保留人工状态。生产 fixture 默认关闭，显式启用也仅限开发/测试/native-smoke。

## 验收与验证

- GitHub Actions 执行 Java 单元及 PostgreSQL/Valkey 集成测试，验证并发去重、世代 fencing、续租丢失、外部调用无事务、部分失败恢复及审核状态保护；本地不运行 Java/Gradle/Maven/Docker 构建测试。
- 固定随机样本只读重放匹配策略，分别报告拒绝/候选/可批准及明确错季；不以拒绝数量冒充准确率。
- 按受影响模块构建双架构 Native，并通过运行门禁后沿用 GitOps 发布；其他模块不重复构建。
- 发布后核对正常任务调度、连接池、队列和错误状态。既有链接在系统提供安全复核能力前保持原状，不作一次性人工修复。

## 兼容与回滚

现有任务与队列载荷保持可读。现有 version/updated_at 用于执行权，无需删除历史数据。新代码部署期间旧 Pod 可能尚未遵守执行世代，滚动完成前不宣称并发隔离全部生效。回滚使用上一不可变镜像；新增安全校验会降低自动批准数量，待审核数量可能上升，属于明确展示的保守行为。

### 关键变更

1. `MagnetSearchExecutor` 编排源站调用、匹配判定及失败恢复；`MagnetQueryService` 保留原有管理接口并委派搜索，外部 HTTP 和流控等待不占用事务。
2. `MagnetSearchJobCoordinator` 使用作品行锁、执行世代和有效租期保护短事务；重复 API 入队复用任务，正常领取有界合并无执行历史的重复任务；已有 provider run 仍保留。
3. `DistributedMagnetWorkSubmissionStore` 原子发布一次，保留活跃 claim、终态和重试预算，同时沿用公共队列事件与速率指标。`MagnetPendingWorkRecovery` 有界补投遗漏消息，并按队列实际终态 SUCCESS/PERMANENT_FAILURE 对齐已废弃任务，不复活 DLQ。
4. `MagnetQueueClaimGuard` 与数据库执行续租协同；等待其他执行者时不消耗业务重试，defer 更换 submission token 防止旧令牌复活。成功源和有效空结果不重复请求，明确永久失败不会无限重试。
5. `MagnetCandidateIdentityPolicy` 区分拒绝、待审核和可自动批准，使用真实返回 ID/标题/年份/季数及分类约束；查询回显和旧 provider 分数不再作为身份证明。保留 APPROVED/REJECTED/HIDDEN 审核状态，链接写入使用 PostgreSQL 原子 upsert。
6. 修正 Base32/十六进制哈希等价处理、异常响应分类与 fixture 隔离；未知/错误页不再成为成功空结果，fixture 仅在显式开关和限定测试 profile 同时满足时启用。
