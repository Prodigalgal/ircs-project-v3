# CF 代理连接重试

CF 订阅每次提供一批 16 个不同节点。同步器对临时拉取故障进行有限重试，收到完整且有效的批次后可写入候选配置。已生效配置及其摘要继续控制生产部署，候选批次单独验活。

HTTP CONNECT 经现有网关的本地 SOCKS5 入站连接到指定节点。收到成功回执后，网关向客户端确认隧道并双向转发。每个 CONNECT 最多使用 3 个不同节点，每次握手 2 秒，总预算 6 秒。节点失败后进入带抖动的冷却，冷却到期由一个待处理请求试探同一节点。健康状态优先沿用 sing-box 的选路和探测结果。普通 HTTP 请求使用既有路径。

原来的 HTTP 入站在真正建立出站连接前返回了 200。隔离测试中，首选节点拒连或握手挂起时，旧方案没有使用备用节点。通过 SOCKS5 等待实际连接确认后，1、8、32 并发各 32 个请求均完成。两条线路都失败时，网关返回 502，源站命中为零。测试还覆盖冷却后恢复、普通 HTTP 转发、隧道建立后断流和源站 403、429。

生产每个网关 Pod 运行一个 sing-box。局部失败在同一个实例内切换节点，Oracle 入口沿用已有配置，出口目的地址检查适用于新增的 SOCKS5 入站。VLESS 鉴权晚于回执的故障由既有客户端重试与节点验活处理。

发布配置以 GitOps 中的 `ircs-prod/core/06-proxy-pools.yaml` 和 `proxy-connect-retry.py` 为准。上一不可变部署使用仍被引用的 `shared-config.json`，可切回上一 GitOps 配置。
