# IRCS 5.0 数据模型重建

## 范围与发布

5.0.0 在现有仓库内统一交付目录、来源采集、资源、用户互动、配置和运营数据模型。生产使用新库和独立的消息、搜索、缓存及对象存储命名空间。迁移保留历史变更记录，5.0 结构由新的 Liquibase 变更管理。上线保留正在使用的来源配置、凭据、集成配置与停用的采集计划。停采开关贯穿发布与验收。

公开页面保留现有作品访问地址。公开目录条目 UUID 与作品、季集的内部 UUID 分别管理。内部搜索消息使用 `CATALOG_ENTRY` 与 `SOURCE_RECORD`。新旧发布候选使用各自的队列和索引，切换时保留旧版可用制品。

## 数据归属

| 写入域 | 所有权与关系 |
| --- | --- |
| 目录 | 作品拥有规范季集、标题、权威标识和主创事实。发布条目持有公开 UUID，指向作品或某一季。 |
| 采集 | 站点配置与网络源分开。计划管理时间与范围，执行记录保存参数和生命周期。来源记录按上游键去重，输入变化产生可复核版本。 |
| 聚合与播放 | 归属证据记录候选和输入。当前绑定明确来源对应的作品、季集与公开条目。播放验证和可用性检查独立，不能跨作品引用。 |
| 素材 | 图像来源、内容资产、存储位置和回收任务各有主键。删除最后一个活动引用后，回收任务复核物理对象是否仍被使用。 |
| 用户 | 账号与外部登录身份分开。全局求片需求与个人提交分开。积分流水、余额和提交在同一事务内更新。续播可记住上次线路，进度关联规范季集。 |
| 检索与运维 | 简介投影和变更记录可重放。索引、缓存、榜单以及运行统计可由所属事实重建。 |

来源优先适用于缺少可靠权威标识的短剧、体育、新闻等类别。来源证据保存观察版本，源站标题、海报、播放线路变化时可以回看原始输入。权威导入按提供方身份合并到同一作品，季集确认后才能对外暴露可验证的播放关系。主创输出优先读取作品及季级演职员表，来源显示名可以在对应角色尚无结构化记录时展示。

## 验证与切换顺序

1. 使用 `native-build.yml` 的 `verify_only` 对受影响模块运行构建检查和真实 PostgreSQL 回归。迁移测试从新库运行完整的 Liquibase 变更集，并验证第二次运行的幂等性。
2. 为通过回归的提交保留正式业务版本，再构建不可变的 JDK 25 Native、前端和分类服务候选。候选期间的数据库、缓存、索引和对象路径与生产 4.1.1 隔离。
3. 停止旧版写入后，将来源配置、凭据、字典和停用计划写入新库。数据库、服务镜像及数据命名空间随同一 GitOps 切换交付。检查调度仍为停用、全部部署就绪和新库业务表为空，再开放前台。

## 验收条件

- 空库能够通过 native migrator 初始化。重复运行保持主键、默认配置和 5.0.0 版本标签一致。
- 同名作品可独立存在。不同作品或错误季集之间的绑定被数据库拒绝。采集记录重复投递可幂等回放，变更数据留有可追溯输入。
- 同一资源被多条目录或来源引用时安全回收。不同用户对同一作品的求片提交可独立查看，扣分可按提交幂等重放。
- 两套前端、Java 25 native 服务、消息消费者和搜索投影通过 GitHub Actions 检查。生产以同一次验收的不可变制品执行切换。
