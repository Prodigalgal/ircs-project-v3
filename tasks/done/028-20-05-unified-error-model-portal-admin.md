# 028-20-05 unified error model and portal/admin compatibility

Status: done

## Goal

Unify external and internal HTTP error responses across V3 services and BFFs so portal/admin can parse one stable envelope while preserving business status, code, message, trace, and correlation semantics.

## Scope

- Added shared `ApiErrorResponse`, `ApiErrorResponses`, and `CommonApiExceptionHandler` in `shared:ircs-common`.
- Updated identity/content/storage/interaction/ops service exception handlers to emit the shared envelope.
- Replaced hand-written config/catalog/JWT filter HTTP errors with shared response helpers.
- Covered BFF-owned route/target errors through common advice and added admin/portal BFF MockMvc contract tests.
- Kept upstream BFF proxy behavior as transparent streaming pass-through; upstream services now own their unified error envelope.

## Contract

HTTP error responses now use:

```json
{
  "timestamp": "...",
  "status": 404,
  "error": "Not Found",
  "code": "http.404",
  "message": "No BFF route for /api/v1/not-allowed",
  "entity": "http",
  "path": "/api/v1/not-allowed",
  "traceId": "trace-admin",
  "correlationId": "corr-admin",
  "details": {}
}
```

`details` is omitted when empty. Responses also include `X-Trace-Id` and `X-Correlation-Id`; missing IDs are generated by the shared helper.
